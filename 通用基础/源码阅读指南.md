# Linux 源码阅读方法

## 固定环境

- 工作区源码版本：Linux v6.17.7。
- 源码目录：`linux/`，由 `脚本/获取Linux源码.sh` 准备；完整源码不纳入 Git。
- 每篇 Linux 笔记写出版本、源文件相对路径、关键符号和访问日期；源码更新后重新核对代码摘录。

## 阅读流程

1. 把问题写成一句话，例如“DTB 怎样变成内核可遍历节点？”
2. 查内核文档、API 注释或 binding，先知道术语与约束。
3. 找最小 DTS/驱动示例，辨认输入数据和预期行为。
4. 搜索结构体、函数或宏定义，再看调用者和被调用者。
5. 每次沿一条主线向前/向后一层，记下控制流和数据流；遇到架构相关实现，明确标记架构。
6. 仅复制理解关键点所需的短代码片段，标明 SPDX/许可、版本、路径、函数名；优先链接上游文件。
7. 用自己的话画流程或解释不变量，回答自测题。
8. 回到目标问题，写结论、疑问和下次阅读入口。

## 工具方法

- VS Code：`Ctrl+Shift+F` 搜符号；F12 跳定义；Shift+F12 查引用；Alt+← 返回。巨型源码树不需要开启全文自动索引或递归文件监视。
- 命令行：`grep -R` 或 `git grep` 搜符号；`sed -n '起始,结束p'` 读局部；`git blame` 看行变更背景（需要 Git checkout）。
- Geany 等轻量编辑器适合逐文件浏览；用终端 `less -N file` 可带行号阅读。
- 对源文件的摘录要保留上下文，不能只看一个函数就推断全系统行为。
