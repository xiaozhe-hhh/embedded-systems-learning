# 计算机组成、地址空间与总线

## 阅读顺序

CPU 与寄存器 → 内存层次 → 地址空间 → 总线/互连 → MMIO 与 DMA。学习具体板子时再对照 SoC 手册和内存映射表。

## 核心模型

CPU 执行指令并通过寄存器、缓存和内存层次访问数据。程序看到的虚拟地址经 MMU 转换为物理地址；物理地址空间可以映射 RAM，也可以映射设备寄存器。MCU 裸机环境可能没有虚拟内存，但地址仍需由芯片存储器映射定义。

- **寄存器**：CPU 内部少量高速状态；不要与外设寄存器混淆。
- **缓存**：降低平均访存延迟；DMA 与缓存一致性需要平台/驱动框架正确维护。
- **总线/片上互连**：连接主设备与从设备，承担地址、数据及控制/事务传输；现代 SoC 常使用复杂互连网络，不一定是单一共享总线。
- **MMIO**：设备寄存器被映射到地址空间。访问需遵守体系结构和 OS 的 I/O 访问规则；Linux 驱动通常使用 `ioremap`/`readl`/`writel` 等接口，不直接解引用普通指针。
- **DMA**：设备直接与内存交换数据，减少 CPU 搬运；仍需配置缓冲区、方向、映射、同步和生命周期。

## 地址与资源

地址不是资源本身的抽象名称：设备手册给出的总线地址可能还要经过桥接/转换。Linux 设备树中的 `reg` 由父总线的 `#address-cells` 和 `#size-cells` 解释；不要将 DTS 中的数字不加分析地当作 CPU 虚拟地址。

## 易错点

- CPU 指针、物理地址、DMA 地址不一定相等。
- MMIO 区域具有读写副作用；不可随意缓存、合并或重复访问。
- 外设寄存器的读改写可能丢更新或触发副作用，需要查手册并考虑并发。
- DMA 缓冲区完成传输不等于 CPU 缓存自动与设备一致。
