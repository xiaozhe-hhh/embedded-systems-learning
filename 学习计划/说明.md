# 嵌入式学习与实习计划

## 目标与前提

总体目标：以 Linux 驱动为主线，穿插通用基础面试知识和《代码随想录》；用一周左右快速复习 RTOS，再完成一个 MCU + RTOS 项目和一个 Linux 驱动项目，争取在 **2027 年 2–3 月开始投递实习**。

你已学过 MCU、Qt、应用编程和 RTOS，对 MCU 相对熟悉，因此计划不从零重学 MCU，而是把时间优先给 Linux 驱动和项目。科研任务优先级更高，学习节奏按学习单元顺延，不为赶日期牺牲科研、休息或理解质量。

计划基线为每周约 4–5 个学习单元，每个 60–90 分钟；有余力再加，不要求每天都学习。每个单元只安排一条主线，并在[每日学习日志](../每日记录/说明.md)记录实际完成情况。

## 每周节奏

### 常规学习周

- **3 个主线单元**：Linux 驱动概念、内核源码和小实验。
- **1 个基础复习单元**：C、操作系统、计算机组成、数据结构、编译链接或网络协议，按周轮换。
- **1 个算法单元**：按《代码随想录》当前章节做 1–2 题，重点写思路、复杂度和错因。

### 速通/项目周

阶段任务需要集中时间时，把主线单元用于 RTOS 速通或项目实现；基础复习和算法可以维持每周各 1 个短单元。科研忙时可减到 2–3 个学习单元，后续整体顺延。

## 阶段路线

### 阶段 1：Linux 驱动基础与设备树（2026 年 11 月）

**重点**：设备树语法、binding、reg/address-cells、interrupts、pinctrl/clock/reset；DTS 到 DTB；FDT 交接、内核早期扫描和 unflatten；OF 节点创建 platform device；平台驱动匹配与 probe。

**每周穿插**：C 指针/内存、编译链接、内存映射 I/O；《代码随想录》数组、哈希、字符串或链表基础题。

**阶段产出**：能选一个 DTS 节点解释其资源；沿 Linux v6.17.7 源码画出 DTB 到 platform device/driver 的主路径。字符设备、并发与竞争、中断与异常以复盘和源码追踪为主，不重复从零铺开。

### 阶段 2：Linux 驱动机制深化（2026 年 12 月）

**重点**：字符设备/VFS 调用路径、platform driver、MMIO 与资源管理、IRQ 和 threaded IRQ、并发同步、等待队列/completion、workqueue/timer；按需看 `poll`、`ioctl`、sysfs/debugfs 和 DMA 基础。

**每周穿插**：操作系统、网络/总线、C 内存模型等常见面试题；《代码随想录》链表、栈/队列、二叉树等章节。

**阶段产出**：完成若干小型驱动练习；能解释 probe/remove、错误回滚、devm 生命周期和中断上下文约束；整理一份 Linux 驱动面试复习清单。

**动手环境提醒**：阅读源码固定参考 Linux v6.17.7；编译模块时必须使用与目标板正在运行的内核版本、配置和架构相匹配的 headers/build tree，不能假定下载的阅读源码与运行内核相同。

### 阶段 3：RTOS 快速复习与 MCU + RTOS 项目（2027 年 1 月）

**RTOS 速通（约 1 周）**：用已有知识快速过一遍任务状态/调度、队列、信号量与互斥锁、软件定时器、ISR 与任务协作、优先级反转、任务栈和内存管理。薄弱处再回到官方文档，不重学熟悉内容。

**项目（约 2–3 周）**：选熟悉的 MCU/RTOS 和手边已有外设，完成一个可演示的小项目。建议包含清楚的任务划分、至少一种队列或同步机制、定时采集/通信、错误处理和看门狗（适用时）。不要为项目额外购买硬件作为前置条件；优先用已有板卡和模块。

**阶段产出**：可构建的代码、模块/任务图、关键设计说明、运行截图或串口日志、已知限制和复盘。同步整理一个项目 README，突出本人负责的设计与调试过程。

### 阶段 4：Linux 驱动项目（2027 年 2 月）

从手边硬件和目标板能力中选范围合适的项目，不先假定具体外设。建议组合设备树、platform driver、资源获取、中断/延后处理和用户态验证；项目要有明确问题、可复现步骤和可读代码。硬件不适合时，选择能在现有板卡或虚拟环境完成的驱动练习。

**阶段产出**：项目代码和 README、设备树/驱动/用户态的关系图、构建与运行步骤、关键源码路径、调试记录、演示材料和项目复盘。

### 阶段 5：投递与补强（2027 年 2–3 月）

不必等所有笔记和项目都“完美”才开始投递。Linux 项目有可演示的最小版本、MCU + RTOS 项目有清晰文档后，就开始投递并继续改进。

- 整理简历与 GitHub 项目主页，明确 Linux 驱动、MCU/RTOS 和调试经历。
- 每周做 1 次基础知识口述/模拟问答，重点复习错题和项目追问。
- 根据岗位要求补缺口，持续投递、记录反馈并迭代项目说明。
- 若科研或项目进度挤压时间，优先保住 Linux 项目最小可演示版本，其他拓展项顺延。

## 基础八股与《代码随想录》轮换

### 基础知识复习

每周安排 1 个基础单元，按下面顺序轮换；遇到不会口述的主题，下一周先复习错题，再继续新主题。

1. C 指针、数组/结构体、内存布局和常见未定义行为。
2. 进程/线程、用户态/内核态、系统调用和调度。
3. 并发同步：互斥、自旋锁、原子操作、死锁和上下文限制。
4. 计算机组成：地址空间、MMIO、总线、缓存一致性和 DMA。
5. 编译、链接、ELF、交叉编译工具链和调试。
6. 数据结构复杂度与常见实现取舍。
7. 网络与通信：TCP/UDP、UART/I2C/SPI/CAN/RS-485。
8. Linux 驱动专题口述：设备树、platform bus、字符设备、中断、probe 生命周期。

第二轮起以面试问答和错题复盘为主，答案尽量结合自己的源码阅读或项目经历。

### 《代码随想录》

把它作为算法基础和面试表达训练，不与 Linux 主线争夺每天时间。每周 1 个学习单元，通常完成 1–2 道题：先独立思考，再对照讲解，最后隔天复做错题。

- **11 月**：数组、哈希、字符串、链表基础。
- **12 月**：栈与队列、二叉树核心遍历和常见题型。
- **1 月**：回溯、动态规划入门；优先补前面错题。
- **2–3 月**：保持每周一次复做/模拟面试，根据岗位和错题选题。

不要求刷完所有题目才开始投递；重点是能讲清思路、复杂度和边界条件。

## 每个学习单元的记录方式

1. 写明本次学习属于 Linux 主线、基础复习、《代码随想录》、RTOS 速通或项目。
2. 记录实际学习时长和具体阅读的笔记/文档/源码/题目。
3. 用自己的话写 3–5 句总结；源码单元写路径、函数和调用关系。
4. 记录一道自测题、一道算法题的错因，或一个项目提交/调试结果。
5. 标记状态：完成、部分完成、顺延。计划本身不算完成记录。

## 进度检查点

- **2027 年 1 月底**：RTOS 快速复习完成，MCU + RTOS 项目有可演示版本和文档。
- **2027 年 2 月**：Linux 驱动项目形成最小可演示版本，开始整理/投递实习申请。
- **2027 年 3 月**：持续投递、复盘面试反馈、完善项目，并补足岗位要求的知识点。

这些是检查点，不是硬截止日期。实际进度以科研安排、每周复盘和[每日日志](../每日记录/说明.md)为准。
