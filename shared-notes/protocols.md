# 常见通信接口与网络协议

## 阅读顺序

先区分物理/电气层、链路/总线、传输层和应用协议，再分别学习 UART、I2C、SPI、CAN、RS-485、TCP/UDP。

| 接口/协议 | 典型拓扑与特点 | 学习时重点 |
|---|---|---|
| UART | 点对点异步串行，TX/RX，双方约定波特率、数据位、校验和停止位 | 无时钟线；逻辑电平不等于 RS-232/RS-485 电气标准 |
| I2C | 多设备共享两线时钟/数据，带地址、应答和仲裁机制 | 上拉、电容、地址、速率、重复起始、时钟拉伸 |
| SPI | 通常时钟、数据线和片选，常见全双工 | 模式 CPOL/CPHA、位序、片选与具体器件时序 |
| CAN | 多主机差分总线，按标识符仲裁，具备错误检测与重发机制 | 终端电阻、位时序、仲裁 ID 与应用层协议的区别 |
| RS-485 | 差分物理层规范，适合较长距离/多点链路 | 半双工方向控制、终端与偏置；本身不定义上层帧协议 |
| TCP | 面向连接、可靠有序字节流 | 粘包是应用分帧问题；处理重传、拥塞和连接生命周期 |
| UDP | 无连接数据报，不保证可靠交付/顺序 | 应用自行处理丢包、重复、时序和最大报文限制 |
| HTTP/MQTT | 应用层协议 | HTTP 请求/响应；MQTT 发布/订阅及 Broker、QoS 语义 |

## 设计通信帧

明确同步/帧边界、长度、类型、序号、负载、校验、超时和错误恢复。解析时先验证长度和边界，再访问字段；不可直接把网络字节缓冲强转为 C 结构体来依赖填充和端序。

## 易错点

- UART 是传输格式/接口，RS-485 是电气层规范；UART 可通过 RS-485 收发器在 RS-485 总线上工作。
- I2C/SPI/CAN 是总线/链路类方案，TCP/UDP 工作在 IP 传输层，不能直接比较吞吐数值而忽略拓扑和目标。
- TCP 提供字节流，应用必须定义消息边界。
- CRC/校验和用于发现部分错误，不等同于认证或加密。
