# 常用数据结构

## 阅读顺序

从连续内存的数组开始，再学习链表、栈/队列和哈希表；最后比较它们在嵌入式内存与实时约束下的代价。

| 结构 | 常见操作 | 时间复杂度 | 主要代价与适用场景 |
|---|---|---|---|
| 数组 | 下标访问 O(1)，中间插删 O(n) | 连续存储，缓存友好；长度或扩容需管理 | 固定表、环形缓冲区、采样数据 |
| 单链表 | 已知节点插删 O(1)，按位置查找 O(n) | 每节点有指针开销，访问局部性弱 | 大量稳定节点、内核链表组织 |
| 栈 | push/pop O(1) | 后进先出 | 调用栈、解析嵌套结构 |
| 队列 | 入队/出队 O(1) | 先进先出 | 生产者消费者、事件排队 |
| 环形队列 | 读写 O(1) | 固定容量、通常数组实现 | UART/DMA 缓冲、避免频繁分配 |
| 哈希表 | 平均查找/插入 O(1)，最坏 O(n) | 哈希冲突、扩容和内存开销 | 由键快速查找对象 |

复杂度是渐进上界/平均模型，不包含缓存失效、锁竞争、动态分配失败等实际代价。硬实时路径应考虑最坏执行时间，通常避免不可控扩容和不确定分配。

## 环形队列索引

容量为 2 的幂时，索引可按 `index & (capacity - 1)` 回绕；但必须明确空/满区分策略，例如保留一个槽位，或维护独立计数/单调递增序号。多生产者/多消费者场景还需要同步，单线程环形队列代码不能直接当成无锁队列。

## 链表注意点

操作前确认节点生命周期、并发访问规则和删除后的引用有效性。Linux 内核 `list_head` 是侵入式双向链表：链表节点嵌入业务结构体，遍历时通过 `container_of()` 找回容器。
