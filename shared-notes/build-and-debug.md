# 编译、链接与调试工具

## 编译流程

```text
源文件 → 预处理 → 编译成汇编 → 汇编成目标文件 → 链接成可执行文件/镜像
```

- 预处理展开头文件和宏；编译检查语言并生成汇编；汇编生成目标文件；链接解析符号、合并段并重定位地址。
- `.o` 目标文件通常仍包含待解析符号；静态库是目标文件归档，动态库在运行时装载/解析。
- 交叉编译器运行在主机上，但生成面向目标架构/ABI 的程序。工具链前缀、sysroot、C 库和 ABI 必须匹配目标系统。
- Bootloader、内核和 MCU 固件的链接脚本会影响段布局与加载地址；链接成功不代表镜像一定符合目标板启动格式。

## 常用工具

- `gcc -E/-S/-c`：分别观察预处理结果、汇编和目标文件。
- `nm`：查看符号；`readelf -h -S -s`：检查 ELF 头、段/节和符号；`objdump -d`：反汇编。
- `make V=1`：观察构建命令；Kbuild 常用 `make ARCH=... CROSS_COMPILE=...`。
- `gdb`：断点、单步、查看变量与调用栈；嵌入式常配合 gdbserver/OpenOCD/J-Link 等。
- `dmesg`、串口控制台、`/proc` 和 `/sys`：Linux 目标机排查入口。

## 排错顺序

1. 先复现并记录完整错误、配置和版本。
2. 判断问题属于编译、链接、加载、启动还是运行时。
3. 检查目标架构、工具链、头文件、库和链接脚本。
4. 通过最小例子缩小范围，再用符号表、反汇编、日志和调试器验证。
5. 修改一个因素并复测，记录最终解决原因。
