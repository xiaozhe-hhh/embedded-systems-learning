# C 语言与内存基础

> 定位：嵌入式方向复习材料。结合实际编译器和目标 ABI 验证细节；不要把某个平台的实现当成 C 语言标准保证。

## 阅读顺序

1. 先理解对象、类型、生命周期和存储期。
2. 再学指针、数组、结构体与函数指针。
3. 最后联系内存映射 I/O、中断共享状态和链接器布局。

## 对象、地址与指针

对象是具有类型、存储期和生命周期的内存区域。指针保存对象地址，指针的类型决定解引用时如何解释该地址以及指针运算的步长。

```c
int values[4] = {10, 20, 30, 40};
int *p = values;          /* 数组表达式在此处转换为首元素指针 */
int second = *(p + 1);    /* 等价于 values[1]，结果是 20 */
```

数组不是指针。数组名在大多数表达式中会转换为首元素指针，但 `sizeof array` 得到整个数组字节数；函数形参写作 `int a[]` 时实际调整为 `int *a`，长度需要另行传递。

指针只能在有效对象生命周期内使用。悬空指针、越界指针运算、错误对齐和错误类型转换都可能导致未定义行为。

## `const`、`volatile`、`static`、`extern`

- `const T *p`：通过 `p` 不可修改所指对象；`T * const p`：指针本身不可改指向。
- `volatile`：要求编译器按抽象机规则执行对该对象的可观察访问，常见于 MMIO 或硬件异步更新的对象。它**不**保证原子性、线程间同步或内存屏障。
- `static` 在文件作用域限制名称链接属性为内部链接；在块作用域使对象具有静态存储期。
- `extern` 通常声明在其他翻译单元定义的外部对象或函数。

共享变量同步应使用锁、原子操作或内核/RTOS 提供的同步原语；不能用 `volatile` 替代。

## 结构体、对齐与位域

结构体成员按 ABI 对齐要求布局，成员间可能有 padding。`sizeof(struct T)` 不一定等于成员大小之和。跨编译器、跨 ABI 或硬件寄存器场景，不要假定位域布局和字节序；需要稳定外部格式时明确编码/解码字节。

```c
struct packet_header {
    uint8_t type;
    uint32_t length; /* 中间通常可能有对齐填充 */
};
```

硬件寄存器宜按芯片手册和架构要求使用明确宽度的访问函数/类型，并处理端序、对齐和访问副作用。

## 函数指针与回调

驱动常通过函数指针表提供操作接口。函数指针的签名必须兼容；把对象指针随意转换成函数指针不具备可移植性。

```c
struct ops {
    int (*read)(void *ctx, uint8_t *buf, size_t len);
};
```

## 易错点

- `sizeof(pointer)` 是指针本身大小，不是它指向的数组大小。
- 返回局部自动变量地址会在函数返回后失效。
- 有符号整数溢出在 C 中是未定义行为；无符号运算按模数回绕。
- `memcpy` 的源和目标重叠时行为未定义，应使用 `memmove`。
- MMIO 与普通 RAM 不同，寄存器读写可能有清零、FIFO 弹出等副作用。
